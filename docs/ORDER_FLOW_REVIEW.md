# 주문 처리 흐름 검토

검토일 2026-08-13 · 검토 MedIT
대상 자체 사이트 (chewgumi GitHub Pages) 무통장입금 기준

---

## 1. 전체 흐름

```
주문 접수 → 입금 대기 → 입금 확인 → 배송 준비 → 발송 → 배송 완료
                ↓            ↓           ↓        ↓         ↓
              취소         취소/환불    취소/환불   환불      환불
```

**주문 상태 7가지** — pending(입금대기) / paid(결제완료) / preparing(배송준비) /
shipping(배송중) / delivered(배송완료) / cancelled(취소) / refunded(환불)

데이터베이스에 제약 조건으로 걸려 있어 다른 값은 저장되지 않습니다.

## 2. 단계별 점검

### ① 주문 접수

| 항목 | 상태 |
|---|---|
| 재고 확인 | 정상 — 부족하면 주문 거부 |
| 금액 재계산 | 정상 — 서버에서 다시 계산 (조작 방지) |
| 쿠폰 검증 | 정상 — 유효기간·최소금액 확인 |
| 주문번호 발급 | 정상 — 날짜+일련번호 |
| 입금기한 설정 | 정상 — 7일 |
| 사장님 알림 | 이메일·웹푸시 |
| 고객 안내 | 계좌 정보 화면 표시 |

**확인 결과** 항목 없는 주문 0건, 금액 불일치 0건

### ② 입금 확인 (수동)

운영자가 은행에서 확인 후 [입금확인] 클릭

| 처리 | 상태 |
|---|---|
| 상태 변경 pending → paid | 정상 |
| 결제일시 기록 | 정상 |
| 재고 차감 | 정상 |
| 적립금 지급 (1%) | 정상 |
| 고객 안내 | 발송 대기로 기록 |

### ③ 발송

| 처리 | 상태 |
|---|---|
| 운송장 번호 필수 검증 | 정상 |
| 택배사 자동 인식 | 정상 (자릿수 기반 4개사) |
| 상태 변경 → shipping | 정상 |
| 고객 배송 안내 | 발송 대기로 기록 |
| 배송 조회 연결 | 정상 |

### ④ 취소

| 시점 | 처리 | 상태 |
|---|---|---|
| 입금 전 | 재고 복원 · 쿠폰 복원 | 정상 |
| 입금 후 | 재고 복원 · 적립금 회수 · 쿠폰 복원 | 정상 |
| 취소 사유 필수 | | 정상 |
| 이력 기록 | | 정상 |

### ⑤ 환불

| 처리 | 상태 |
|---|---|
| 환불 금액 입력 | 정상 |
| 계좌 정보 입력 | 정상 |
| 환불 사유 기록 | 정상 |
| 상태 변경 → refunded | 정상 |

**확인 결과** 사유 없는 취소 0건, 금액 없는 환불 0건

## 3. 발견된 문제

### 문제 1 — 실제 환불 송금은 수동입니다

**현황** 환불을 실행하면 기록만 남고, 실제 돈은 운영자가 은행에서 직접 보내야 합니다.

**영향** 환불 기록은 있는데 송금을 잊으면 고객 민원이 됩니다. 확인할 방법이 없습니다.

**대응** 이지페이 본계약 후 PG 환불 API 연동 시 자동화됩니다.
그전까지는 **환불 완료 체크 기능**을 넣어 "송금함/안 함"을 구분해야 합니다.

### 문제 2 — 입금 기한이 지나도 자동 취소되지 않습니다

**현황** 7일이 지난 미입금 주문이 그대로 남습니다.
재고가 묶여 있고, 목록이 계속 쌓입니다.

**영향** 지금은 주문이 적어 문제없지만, 늘어나면 재고 관리가 어려워집니다.

**대응** 자동 취소 기능이 필요합니다.
카페24는 이 기능을 제공합니다(7일 후 자동취소 설정됨).
자체 사이트에도 동일하게 넣어야 합니다.

### 문제 3 — 알림이 실제로 나가지 않습니다

**현황** 고객 안내(입금·발송)가 "발송 대기"로만 쌓입니다.
문자 발송 경로가 없기 때문입니다.

**영향** 고객이 주문 후 아무 연락을 못 받습니다.

**대응** 다음 중 하나
- 카페24 SMS 사용 설정 + 충전 (건당 20원)
- 고객에게 이메일 발송 (무료, 이메일 수집 필요)
- 웹 푸시 (무료, 고객이 알림 허용 필요)

### 문제 4 — 부분 취소·부분 환불이 없습니다

**현황** 주문 전체만 취소·환불할 수 있습니다.
3개 중 1개만 반품하는 경우를 처리할 수 없습니다.

**영향** 지금은 드물지만, 여러 상품을 함께 주문하는 경우가 늘면 필요해집니다.

**대응** 당장은 전체 취소 후 재주문으로 처리 가능합니다.
필요해지면 품목별 취소 기능을 추가합니다.

### 문제 5 — 교환 절차가 없습니다

**현황** 취소·환불만 있고 교환이 없습니다.

**대응** 실무상 "환불 후 재주문"으로 처리하시면 됩니다.
카페24에는 교환 기능이 있으므로 공식몰 주문은 그쪽에서 처리하시면 됩니다.

### 문제 6 — 환불 규정이 명시되어 있지 않습니다

**현황** 이용약관에 청약철회·환불 조건이 구체적으로 없습니다.

**영향** 분쟁 시 근거가 약합니다. 전자상거래법상 표시 의무가 있습니다.

**대응** 아래 내용을 약관·이용안내에 추가해야 합니다.
- 단순 변심: 수령 후 7일 이내, 왕복 배송비 구매자 부담
- 상품 하자·오배송: 7일 이내(하자 인지 후 30일 이내), 배송비 판매자 부담
- 환불 불가: 식품 특성상 개봉·훼손된 상품
- 환불 처리 기간: 반품 확인 후 3영업일 이내

## 4. 우선순위

| 순위 | 항목 | 사유 | 소요 |
|---|---|---|---|
| 1 | **환불 규정 명시** | 법적 의무 · 분쟁 대비 | 1시간 |
| 2 | **고객 알림 발송** | 고객이 연락을 못 받음 | 설정만 |
| 3 | **환불 완료 체크** | 송금 누락 방지 | 1시간 |
| 4 | **미입금 자동 취소** | 재고 묶임 방지 | 2시간 |
| 5 | 부분 취소 | 필요해지면 | 반나절 |
| 6 | 교환 절차 | 환불+재주문으로 대체 가능 | — |

## 5. 이지페이 계약 후 달라지는 것

| 항목 | 현재 | 계약 후 |
|---|---|---|
| 입금 확인 | 수동 (은행 확인) | 자동 (가상계좌) |

| 결제 취소 | 해당 없음 | 승인 취소 가능 |

**계약 하나로 문제 1과 문제 2가 대부분 해결됩니다.**
