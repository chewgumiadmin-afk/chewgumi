# 「고칠 것」을 적는 형식

조사하는 쪽과 고치는 쪽이 다릅니다.

```
조사   예약 작업(리서치)  →  GitHub 이슈에 「고칠 것」을 적는다.  코드는 안 고친다.
반영   Claude Code        →  그 이슈를 읽고 실제로 고친다.
```

사이에 사람이 없습니다. 그래서 **읽는 쪽이 기계적으로 집어낼 수 있는 모양**이어야 합니다.
줄글로 적으면 반영하는 쪽이 매번 이슈 전체를 다시 해석해야 하고, 무엇이 이미
반영됐는지도 알 수 없습니다.

---

## uxcheck 와 무엇이 다른가

츄구미에는 이미 검출 체계가 하나 있습니다. 둘은 **다른 일을 합니다.**

| | `scripts/uxcheck.py` | `tools/fixes.py` (이 문서) |
|---|---|---|
| 찾는 것 | 기계가 규칙(R1~R15)으로 잡아내는 것 | 사람·리서치가 **조사해서 알아낸** 것 |
| 이슈를 | **직접 올립니다** | 올리지 않습니다 — 조사한 쪽이 적습니다 |
| 중복을 막는 열쇠 | 지문 `<!-- uxcheck:fp=… -->` | `id` 칸 |
| 막는 것 | 같은 이슈가 **또 올라오는 것** | 같은 것을 **또 고치는 것** |

겹치지 않습니다. uxcheck 가 올린 이슈에 **고치는 법을 알아냈다면 `fix` 칸을 댓글로
달아도 됩니다.** 지문은 그대로 두십시오 — 지우면 uxcheck 가 같은 이슈를 또 만듭니다.

---

## 모양

이슈 본문에 `## 고칠 것` 절을 두고, 그 안에 **`fix` 로 표시한 칸**을 항목마다 하나씩 둡니다.

````markdown
## 고칠 것

```fix
id:     CG-158-1
파일:   checkout.html:412,588,731
무엇:   cg_sb 를 직접 읽어 만료된 토큰으로 요청이 나갑니다
어떻게: JSON.parse(localStorage.getItem('cg_sb')).t 세 자리를 cgTok() 으로 바꿉니다
확인:   python3 scripts/uxcheck.py 의 R8 에서 checkout.html 이 빠짐 + 테스트 결제 1건
막는것: 결제 길목입니다. 대표님 확인이 먼저입니다
상태:   대기
```
````

칸 밖에는 사람이 읽을 설명을 얼마든지 써도 됩니다. **칸 안만 기계가 읽습니다.**

## 칸에 들어가는 것

| 열쇠 | 뜻 | 규칙 |
|---|---|---|
| `id` | 이 항목의 이름표 | `<저장소>-<이슈번호>-<순번>`. 한 번 붙이면 안 바꿉니다 |
| `파일` | 고칠 자리 | 저장소 뿌리에서 본 경로. 줄을 알면 `경로:줄`. 여럿이면 쉼표 |
| `무엇` | 무엇이 잘못됐나 | 한 줄. 증상이 아니라 원인 |
| `어떻게` | 어떻게 고치나 | 반영하는 쪽이 그대로 따라 할 수 있게 |
| `확인` | 고쳐졌는지 어떻게 아나 | 돌릴 명령이나 눈으로 볼 기준 |
| `막는것` | 먼저 정해져야 할 것 | 없으면 `없음`. 있으면 **무엇을 누가 정해야 하는지** |
| `상태` | 지금 어디까지 | `대기` · `반영됨 · <커밋>` · `보류 · <까닭>` |

## 규칙

**`막는것: 없음` 이면 사람 확인 없이 반영해도 되는 것입니다.** 반영하는 쪽은 이것만
골라서 바로 처리합니다. 그러니 조사하는 쪽은 **사람이 정해야 할 것이 하나라도 있으면
반드시 `막는것` 에 적어야 합니다.** 비워 두면 확인 없이 고쳐집니다.

**아래는 `막는것` 을 반드시 채웁니다.** 오픈을 앞둔 자사몰입니다.

```
· 손님 화면의 문구·디자인          이슈 #108 (UX-RULES R16)
· 결제 길목                        checkout.html · pay · 이지페이 전문
· 로그인 길목                      assets/tok.js · assets/guard.js · Supabase 인증 설정
· 주문·회원 데이터의 저장 형식
· 돈이 나가거나 손님에게 나가는 것  환불 실행 · 문자·메일 발송 · 과금
· 열쇠·연결 문자열                 값은 이슈에 절대 적지 않습니다 (#111)
```

R16 은 `docs/UX-RULES.md` 에 없습니다 — 그 문서는 R15 에서 끝납니다.
**R16 은 이슈 [#108] 에서 정한 작업 원칙입니다.** 찾지 말고 #108 을 보십시오.

**한 칸에 한 가지만.** 「A 와 B 를 고친다」는 칸 두 개로 나눕니다. 그래야 A 만 반영하고
B 는 보류하는 것이 됩니다.

**`상태` 는 반영하는 쪽이 고칩니다.** 조사하는 쪽은 언제나 `대기` 로 둡니다.
반영한 쪽이 커밋 해시를 적어 `반영됨 · c7985e3` 로 바꾸면, 다음 번에 또 반영되지 않습니다.

**`id` 는 절대 바꾸지 않습니다.** 이것으로 중복 반영을 막습니다. 항목이 없어졌으면
지우지 말고 `상태: 보류 · 더 이상 해당 없음` 으로 둡니다.

## 읽어 내기

```
python3 tools/fixes.py                 사람이 읽는 표
python3 tools/fixes.py --todo          막는 것 없고 아직 대기인 것만
python3 tools/fixes.py --json          기계가 읽는 목록
python3 tools/fixes.py --report        docs/FIXES.md 를 다시 만듭니다
```

이슈를 직접 받아 오려면 `GITHUB_TOKEN` 이 있어야 합니다. 없으면 저장소에 들어 있는
`docs/FIXES.md` 를 읽으십시오 — 같은 내용을 사람이 읽을 수 있게 적어 둔 것입니다.

## 왜 이렇게까지 하나

예약 작업이 조사한 것이 저장소로 오지 못하고 쌓여 있었습니다. 이슈까지 왔더라도
「고칠 것」이 줄글이면 반영하는 쪽이 매번 처음부터 읽어야 하고, 무엇이 이미 됐는지
몰라 같은 것을 또 고치거나 아예 빠뜨립니다.

`id` 와 `상태` 두 칸이 그것을 막습니다.
