# 반영 멈춤 스위치

> `docs/반영-멈춤스위치.md` · 2026-09-18
> **검색어**: `멈춤` `stop` `재개` `resume` `한꺼번에반영` `apply-gate`

"지금은 건드리지 마세요" 와 "이제 한꺼번에 올려 주세요" 를 한 곳에서 켜고 끕니다.

---

## 무엇이 달라지나

멈춰 두면 반영이 **실패하는 게 아니라 쌓입니다.**
재개하면 쌓인 것이 한꺼번에 나갑니다. 아무것도 잃지 않습니다.

```
평소          gh-put  →  검사  →  GitHub 에 바로
멈춤 중       gh-put  →  검사  →  apply_hold 에 쌓임        (GitHub 은 그대로)
재개할 때     apply-gate resume  →  쌓인 것 한꺼번에  →  GitHub
```

**검사는 멈춤 중에도 돕니다.** 멈춰 있다고 잘못된 변경을 그냥 쌓아 두면,
재개하는 순간 한꺼번에 터집니다. 그래서 검사를 먼저 통과한 것만 쌓입니다.

---

## 쓰는 법

모두 `x-apply-nonce` 헤더가 필요합니다.

```bash
FN=https://psynvpuedzjvytsgdhgg.supabase.co/functions/v1/apply-gate
H=(-H "apikey: $ANON" -H "content-type: application/json" -H "x-apply-nonce: $NONCE")

# 지금 어떤 상태인가
curl -s -X POST $FN "${H[@]}" -d '{"action":"status"}'

# 멈추기
curl -s -X POST $FN "${H[@]}" -d '{"action":"pause","reason":"오픈 준비 중"}'

# 무엇이 나갈지 먼저 보기
curl -s -X POST $FN "${H[@]}" -d '{"action":"resume","dry":true}'

# 재개하며 한꺼번에 내보내기
curl -s -X POST $FN "${H[@]}" -d '{"action":"resume"}'

# 쌓인 것 중 버리기
curl -s -X POST $FN "${H[@]}" -d '{"action":"drop","ids":[3,4]}'
```

## 규칙

### 같은 파일은 마지막 것만 나갑니다

멈춘 동안 `checkout.html` 이 세 번 쌓였다면, 재개할 때 **마지막 것 하나만** 나갑니다.
앞의 둘은 `superseded` 로 남습니다 — 지우지 않고 기록으로 둡니다.

세 번을 차례로 올리면 커밋이 셋 생기고, 중간 판이 잠깐 라이브에 뜹니다.
그게 바로 "충돌"이 생기는 자리입니다.

### 절반만 나간 채로 열어 두지 않습니다

내보내다 한 건이라도 실패하면 **멈춤을 유지합니다.**
나머지는 계속 내보내되, 스위치는 잠긴 채로 둡니다.
실패한 것을 고친 뒤 다시 `resume` 하면 됩니다.

### 급한 것은 통과시킬 수 있습니다

```json
{ "path": "...", "content_b64": "...", "dry": false, "override": true }
```

멈춤 중에도 강제로 씁니다. 손님이 못 사는 문제처럼 기다릴 수 없는 것만.

## 되돌릴 때 (시점 찾기)

나간 것은 `apply_hold.commit_sha` 에 남습니다.

```sql
-- 언제 무엇이 나갔나
select path, applied_at, commit_sha, message
from apply_hold where status = 'applied'
order by applied_at desc limit 20;

-- 특정 시점 이후에 나간 것만
select path, commit_sha from apply_hold
where status = 'applied' and applied_at > '2026-09-18 00:00+09';
```

`dev_drafts` 에는 `prev_sha` 도 있어서 **그 변경 직전 상태**를 알 수 있습니다.
전체를 되감는 것(reset)이 아니라 **그 변경만 빼는 것**(revert)이 가능한 이유입니다.

> 이 부분은 W4 수업에서 규약으로 다듬습니다 — 지금은 기록만 남기는 단계입니다.

## 표 만드는 곳

| | 무엇 | 어디 |
|---|---|---|
| 스위치 | `apply_gate` (한 줄) | Supabase |
| 쌓이는 곳 | `apply_hold` | Supabase |
| 켜고 끄기 | `apply-gate` | Edge Function |
| 실제로 쓰는 것 | `gh-put` v4 | Edge Function |

`apply_gate` · `apply_hold` 둘 다 RLS 가 켜져 있고 익명 정책이 없습니다.
서비스 역할(Edge Function)로만 닿습니다.
