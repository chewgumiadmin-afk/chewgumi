*3주차 · 2026-09-18 · 신현정*
*앞 회차 — W1 `docs/도구-경계-계약서.md` (R-1~R-6) · W2 `docs/단일진실원-규약.md` (R-7~R-14)*

## 0. 이번 주에 푸는 문제

W2 에서 **이슈가 유일한 키**라고 정했습니다. 그런데 이슈를 사람이 손으로 올리면
두 가지가 반드시 무너집니다.

```
① 빠뜨림    화면이 29 장인데 사람이 매번 다 볼 수 없다
② 겹침      같은 문제를 볼 때마다 새 이슈로 또 올린다
```

②가 ①보다 위험합니다. 중복 이슈가 쌓이면 이슈 목록이 신뢰를 잃고,
신뢰를 잃은 목록은 아무도 안 봅니다. 그러면 W2 에서 세운 단일 진실원이 죽습니다.

그래서 이번 주의 산출물은 **검사기**가 아니라 **중복을 안 만드는 검사기**입니다.
검사 로직은 규칙만 옮기면 되는 쉬운 부분이고, 어려운 부분은 지문입니다.

## 1. 지문(fingerprint) — 이번 주의 핵심

### 1-1. 무엇으로 만드나

```
지문 = sha256( 규칙 + 파일 + 증거키 )[:12]

  예)  R2 | subscribe.html | editable:fzip   →  7a17b342b0d3
```

**증거키에 줄번호를 넣지 않습니다.** 이게 전부입니다.

```
✕  R2 | subscribe.html | 200줄      ← 위에 한 줄 추가하면 지문이 바뀐다 → 중복 이슈
✓  R2 | subscribe.html | editable:fzip   ← 코드가 밀려도 같은 문제
```

같은 이유로 증거키에는 **변하는 값**을 넣지 않습니다.
URL 안의 `${id}` 같은 조각은 `*` 로 바꿔서 넣습니다.

### 1-2. 어디에 남기나 — 두 군데

| 곳 | 무엇 | 성격 |
|---|---|---|
| `.uxcheck-state.json` | 지문 → 이슈번호 | **캐시** · 빠름 · 지워져도 됨 |
| 이슈 본문 `<!-- uxcheck:fp=… -->` | 지문 | **기준** · 저장소에 영원히 남음 |

로컬 캐시만 믿으면, 기계를 바꾸거나 캐시를 지우는 순간 전부 다시 올라옵니다.
그래서 등록 직전에 GitHub 검색으로 한 번 더 확인합니다.

```
repo:chewgumiadmin-afk/chewgumi "uxcheck:fp=7a17b342b0d3" in:body
```

**닫힌 이슈도 검색에 걸립니다.** 사람이 "이건 안 고침"이라고 닫아 놓은 것을
도구가 다시 올리지 않는다는 뜻입니다 — 이것이 지문을 이슈 본문에 심는 진짜 이유입니다.

## 2. 새 규칙 R-15 ~ R-20

> W1 은 R-1~R-6 (누가 쓰나), W2 는 R-7~R-14 (무엇이 진실인가).
> W3 은 **기계가 이슈를 올릴 때의 규칙**입니다.

### R-15 · 자동 이슈는 반드시 지문을 품는다

이슈 본문 첫 줄은 `<!-- uxcheck:fp=xxxxxxxxxxxx -->` 입니다.
지문 없는 자동 이슈는 만들지 않습니다. 지우고 다시 올립니다.

### R-16 · 기계는 `[QA][자동]` 으로만 말한다

```
[QA][자동] R2 주소는 찾기로만 · subscribe.html
```

W1 에서 정한 출처 태그를 그대로 씁니다. 라벨은 `src:자동QA`.
사람이 올린 이슈와 기계가 올린 이슈는 제목만 보고 구분돼야 합니다.

### R-17 · 기계는 이슈를 닫지 않는다

올리기만 합니다. 닫기·상태 변경·우선순위 조정은 사람의 일입니다.
기계가 "고쳐진 것 같다"고 판단해 닫으면, 지문이 사라진 자리에 같은 이슈가 또 올라옵니다.

### R-18 · 한 번에 10 건까지

`--max-issues 10` 이 기본값입니다.
첫 실행에서 90 건이 쏟아지면 아무도 안 봅니다. 나눠서 올리고, 나머지는 다음 번에.

### R-19 · 등급이 우선순위를 정한다 — P0 은 "손님이 살 수 없다"

W2 의 P0 정의를 그대로 씁니다.

| 조건 | 라벨 |
|---|---|
| ✕ 버그 **그리고** 구매 동선 화면 | `prio:P0` |
| ✕ 버그 | `prio:P1` |
| ! 주의 | `prio:P2` |

구매 동선 = `index · products · product · cart · checkout · login · join`

### R-20 · 검사는 저장소 **전체**에서 돌린다

`R14 링크가 살아 있어야` 는 "이 폴더에 그 파일이 있나"로 판단합니다.
몇 장만 복사해 놓고 돌리면 멀쩡한 링크가 죽은 링크로 보입니다.

```
✓  git clone 한 폴더에서
✕  화면 몇 장만 내려받은 폴더에서
```

도구가 스스로 눈치채면 R14 를 **주의**로 낮추고 경고를 답니다.
(실제로 이번 주 검사에서 이 보호막이 걸렸습니다 — 3장을 안 받아 놓은 탓이었습니다.)

## 3. 검사 15 가지가 실제로 보는 것

`docs/UX-RULES.md` 의 「검사」 칸을 코드로 옮긴 것입니다.
정적 검사라 **보이는 것만** 봅니다. 그래서 등급을 나눕니다.

| | 규칙 | 실제로 찾는 것 | 등급 |
|---|---|---|---|
| R1 | 값이 있으면 보여주기 | PATCH 는 하는데 화면을 다시 그리지 않음 | ! |
| R2 | 주소는 찾기로만 | 우편번호·주소 칸에 `readonly` 없음 / `daum.Postcode` 없음 | ✕ |
| R3 | 버튼은 반드시 일해야 | `onclick` 이 부르는 함수가 정의돼 있지 않음 (외부 js 포함) | ✕ |
| R4 | 같은 id 는 하나만 | 한 화면에 중복 `id` | ✕ |
| R5 | 무엇이 잘못됐는지 | 「실패했습니다」로만 끝나는 문구 | ! |
| R6 | 돈이 바뀌면 | 수량 입력칸은 있는데 재계산 코드 없음 | ! |
| R7 | 두 번 묻기 | delete·cancel·withdraw 함수에 `confirm` 없음 | ✕ |
| R8 | 로그인 상태 한 곳 | `cg_sb` 직접 읽기 / `exp` 만 보고 `e` 안 봄 | ✕ |
| R9 | 상태에 맞는 메뉴 | LOGIN 과 MYPAGE 가 같이 있는데 `navauth.js` 없음 | ✕ |
| R10 | 고칠 행 지정 | PATCH·DELETE 주소에 `?…=eq.` 없음 | ✕ |
| R11 | 기다리는 동안 | `fetch` 는 많은데 단추 잠금·안내 0 | ! |
| R12 | 개인정보 가리기 | `guest_*` 경로에 마스킹 코드 없음 | ! |
| R13 | 미리 막기 | 주문 상태를 다루는데 단추 숨김 코드 없음 | ! |
| R14 | 링크 살아 있기 | 없는 `.html` 로 보냄 / `http://` 링크 | ✕ |
| R15 | 좁은 화면 | 입력칸 `font-size` < 16px / 단추 높이 < 44px | ! |

### 오탐을 줄이려고 넣은 세 가지

정적 검사는 가만 두면 거짓 경고가 쏟아집니다. 세 군데를 막았습니다.

```
① CSS 덮어쓰기      같은 선택자가 두 번 나오면 나중 것이 이긴다
                    .qty button{height:32px} … .qty button{height:40px}  → 통과
② 본문 글자 무시     "반품" 이라는 낱말이 약관에 있다고 R13 을 올리지 않는다
                    주문 상태를 실제로 다루는 코드가 있을 때만 본다
③ 장식 요소 제외     .btn-close · .icon-btn · ::after 는 44px 규칙에서 뺀다
```

이 셋을 빼기 전 114 건이던 것이 90 건이 됐습니다.
**줄어든 24 건이 전부 거짓 경고였습니다.** 오탐 하나가 규칙 전체의 신뢰를 깎습니다.

## 4. 쓰는 법

```bash
# ① 그냥 본다
python3 scripts/uxcheck.py .

# ② 보고서로 받는다
python3 scripts/uxcheck.py . --report md --out QA-보고서.md

# ③ 올라갈 이슈를 미리 본다  ← 처음에는 반드시 이것부터
python3 scripts/uxcheck.py . --severity bug --github --dry-run

# ④ 진짜 올린다 (새 지문만)
export GITHUB_TOKEN=ghp_xxxx
python3 scripts/uxcheck.py . --severity bug --github --max-issues 10

# ⑤ 등록을 W2 의 gumi.py 에 맡긴다 (규약 검사를 한 번 더 거침)
python3 scripts/uxcheck.py . --severity bug --gumi scripts/gumi.py
```

돌아가는 값 — CI 에서 씁니다.

```
0  버그 없음
1  ✕ 버그 있음
2  토큰이 없어 등록을 못 함
```

## 5. W2 의 gumi.py 와 어떻게 붙나

```
        uxcheck.py                       gumi.py                GitHub
   ┌──────────────────┐            ┌──────────────┐        ┌───────────┐
   │ 화면 29장 읽기    │            │ 제목 규칙 검사 │        │  이슈      │
   │ 규칙 15개 적용    │─ --gumi ──▶│ 라벨 4축 검사  │──────▶ │  라벨      │
   │ 지문 만들기       │            │ 중복 제목 확인 │        │           │
   │ 지문 대조(중복↓)  │            └──────────────┘        └───────────┘
   └──────────────────┘
            └── --github ───────────────────────────────────────▶ (바로)
```

**두 길을 다 열어 둔 이유** — `gumi.py` 는 아직 저장소에 없습니다(§7).
없으면 `--github` 으로 바로 올리고, 들어간 뒤에 `--gumi` 로 바꾸면 됩니다.
`--gumi` 쪽이 규약 검사를 한 겹 더 거치므로 최종적으로는 그쪽이 맞습니다.

## 6. 이번 주 실제 검사 결과

`shop.chewgumi.com` 저장소 **화면 29 장**을 실제로 돌렸습니다.
자세한 것은 함께 드린 `츄구미-검사결과.md`.

```
✕ 버그 25 · ! 주의 65
```

| 규칙 | 건수 | 한 줄 평 |
|---|---|---|
| R8 로그인 상태 | 16 | `cg_sb` 를 화면마다 직접 읽음. 가장 널리 퍼진 문제 |
| R15 좁은 화면 | 50 | 대부분 입력칸 13.5px — **checkout 포함** |
| R2 주소 | 5 | **subscribe.html 에 주소 찾기가 아예 없음** |
| R4 중복 id | 4 | index 에 3개, orders 에 1개 |
| R14 링크 | 5 | 부분 체크아웃 탓 — 전체에서 다시 돌려야 확정 |

### 눈에 띄는 두 건

**① `subscribe.html` — 정기구독 주소를 손으로 칩니다**

```html
<label>우편번호</label><input id="fZip" inputmode="numeric">
<label>주소</label>    <input id="fAddr1">
```

`readonly` 도 없고 `daum.Postcode` 도 안 부릅니다. R2 가 막으려던 바로 그 상황
— **정기구독은 한 번 틀리면 매달 틀린 주소로 갑니다.**
`mypage.html` 은 `fAddr1` 에 `readonly` 가 걸려 있는데, 같은 화면 안의
주문 수정칸 `#eoZip` · `#eoA1` 만 빠져 있습니다.

**② `checkout.html` — 결제 화면에서 아이폰이 확대됩니다**

```css
input,textarea { font-size:13.5px }
```

16px 미만이면 iOS 사파리가 입력할 때마다 화면을 확대합니다.
결제 화면에서 이러면 손님이 매번 손으로 되돌려야 합니다. 구매 동선이므로 P0 입니다.

## 8. 정적 검사가 못 보는 것

솔직하게 적어 둡니다. 이걸 모르면 "통과했으니 괜찮다"고 착각합니다.

```
✕  로그인해야 보이는 화면의 내용
✕  서버가 실제로 무엇을 돌려주는지
✕  JS 가 그려 넣는 요소들 (템플릿 문자열은 일부만 잡힘)
✕  진짜로 눌렀을 때 일어나는 일
```

그래서 `qa-tool.html`(브라우저에서 도는 기존 도구)을 대체하지 않습니다.
**둘은 역할이 다릅니다.**

```
uxcheck.py     푸시할 때마다 · 전체 화면 · 얕게      ← 빠뜨림을 막는다
qa-tool.html   사람이 볼 때 · 한 화면 · 깊게        ← 진짜인지 확인한다
```

## 9. 이번 주에 할 일 — 한 가지

**저장소에 파일을 넣습니다.** Codespaces 터미널에서:

```bash
# 포크에서
git checkout -b qa/uxcheck-w3

mkdir -p scripts docs .github/workflows
cp ~/받은파일/uxcheck.py        scripts/
cp ~/받은파일/자동QA-규약.md     docs/
cp ~/받은파일/uxcheck.yml       .github/workflows/
# W1·W2 파일도 아직 안 들어갔으니 같이
cp ~/받은파일/CLAUDE.md ~/받은파일/AGENTS.md .

# 먼저 무엇이 올라갈지만 본다
python3 scripts/uxcheck.py . --severity bug --github --dry-run

git add -A && git commit -m "QA: uxcheck 도입 (W1~W3 규약 포함)"
git push -u origin qa/uxcheck-w3
# → 원본 chewgumiadmin-afk/chewgumi 로 PR
```

`--dry-run` 을 **반드시 먼저** 돌려 주세요. 올라갈 25 건을 눈으로 보고,
거짓 경고가 있으면 그 규칙을 `--skip-rule R15` 로 빼고 시작하면 됩니다.
