# 브라우저 테스트 시나리오 (E2E)

AI 에이전트(Claude in Chrome · Cowork · GPT Agent)에게 그대로 넘겨서 쓰는 문서입니다.
사람이 직접 따라 해도 됩니다.

**대상** https://chewgumiadmin-afk.github.io/chewgumi/
**최종 갱신** 2026-08-13

---

## ⛔ 절대 하지 말 것

에이전트에게 이 항목을 먼저 읽히세요. 되돌릴 수 없는 동작입니다.

| 금지 | 이유 |
|---|---|
| **[주문하기] 버튼 최종 클릭** | 실제 주문이 생성되고 재고가 차감됩니다 |
| **카드·간편결제 실제 결제** | 진짜 카드가 결제됩니다. 취소해도 정산 내역에 남습니다 |
| **[문자 테스트]·[이메일 테스트] 반복 클릭** | 건당 비용이 발생합니다. 1회만 |
| **[지금 발송] (마케팅 발송)** | 실제 고객에게 광고가 나갑니다 |
| **[입금 확인]·[발송 처리]** | 실제 주문 상태가 바뀌고 고객에게 알림이 갑니다 |
| **[해지]·[취소]·[삭제]** | 실제 데이터가 사라집니다 |
| **카페24 대표운영자 로그인** | 정산 계좌까지 변경 가능한 계정입니다 |
| **AI 개발 도우미의 [사이트에 반영]** | 실제 사이트가 바뀝니다 |
| **Supabase 대시보드 조작** | DB가 직접 변경됩니다 |

**원칙** — 화면을 열고 값을 읽는 것까지만. 데이터를 바꾸는 버튼은 사람이 누릅니다.

## A. 로그인 테스트

### A-1. 관리자 로그인 (자체 사이트)

1. `https://chewgumiadmin-afk.github.io/chewgumi/console.html` 열기
2. 「ADMIN LOGIN」 영역이 보이는지 확인
3. 이메일 칸에 `test@chewgumi.com` 입력
4. 비밀번호 칸에 `Chewgumi!2026` 입력
5. **[로그인]** 클릭
6. **확인** — 로그인 화면이 사라지고 메뉴 카드 13개가 나타나는가
7. **확인** — 각 카드에 「주문 · 배송」「재고 · 품절 관리」「마케팅 발송」 등이 보이는가

**기대 결과** 로그인 성공, 메뉴 표시
**실패 시** 화면에 뜬 오류 문구를 그대로 기록

### A-2. 로그인 유지 확인

1. A-1 성공 상태에서 `orders.html` 열기
2. **확인** — 다시 로그인을 요구하지 않고 바로 주문 목록이 보이는가
3. `stock.html`, `posts.html`, `campaign.html`도 같은 방식으로 확인

**기대 결과** 재로그인 없이 모든 관리 화면 접근

### A-3. 잘못된 정보 처리

1. `console.html`에서 **[로그아웃]** 클릭
2. 이메일 `test@chewgumi.com`, 비밀번호 `wrongpassword` 입력 후 [로그인]
3. **확인** — "로그인 실패: 운영자 계정인지 확인해 주세요." 문구가 뜨는가
4. **확인** — 관리 메뉴가 보이지 않는가

**기대 결과** 접근 차단, 안내 문구 표시

### A-4. 빈 값 처리

1. 이메일·비밀번호를 비운 채 [로그인] 클릭
2. **확인** — "이메일과 비밀번호를 입력해 주세요." 문구

### A-5. 권한 없는 계정 차단

1. 일반 회원 계정으로 `console.html` 로그인 시도
   (계정이 없으면 이 항목은 건너뜀)
2. **확인** — 관리 화면이 열리지 않는가

### A-6. 고객 로그인 화면

1. `login.html` 열기
2. **확인** — 소셜 로그인 버튼(구글·카카오·네이버)이 보이는가
3. **확인** — 하단 안내 문구가 읽기 편한 크기인가 (11px처럼 작지 않은가)
4. **확인** — 「JOIN US」 버튼이 `join.html`로 연결되는가
5. **소셜 로그인 버튼은 클릭하지 마세요** (외부 계정 연동이 실제로 일어남)

## B. 구매 흐름 (주문 직전까지)

### B-1. 상품 탐색

1. `index.html` 열기
2. **확인** — 히어로 배너 4장이 자동으로 넘어가는가
3. **확인** — 배너 이미지와 문구가 일치하는가
   (1번 트리플잇 / 2번 트래블잇 / 3번 듀잇 그레이프 / 4번 듀잇 모델)
4. **확인** — 「All Products」에 상품 11개가 보이는가
5. **확인** — 상품 카드 높이가 모두 같은가 (아래가 들쭉날쭉하지 않은가)
6. **확인** — 「New Arrivals · Triple-it」 카드가 4.5초마다 넘어가는가

### B-2. 상품 상세

1. 「듀잇 4개입」 카드 클릭
2. **확인** — 상세 화면이 열리고 가격 19,900원이 보이는가
3. **확인** — 하단 REVIEW 영역에 후기가 표시되는가
4. **[후기 더 보기]** 클릭 → 후기가 추가로 나타나는가

### B-3. 장바구니

1. 상세에서 **[장바구니]** 클릭
2. `cart.html` 열기
3. **확인** — 담은 상품과 수량이 맞는가
4. 수량을 2로 변경 → **확인** — 금액이 39,800원으로 바뀌는가
5. **확인** — 배송비 2,500원이 표시되는가

### B-4. 주문서 (⚠ 주문하기 클릭 금지)

1. **[주문하기]** 클릭하여 `checkout.html` 진입
2. **확인** — 상품·수량·금액이 장바구니와 일치하는가
3. **확인** — 무통장입금 탭에 계좌가 표시되는가
   → `국민은행 38183704010801 · 예금주 윤소호(츄구미)`
4. **확인** — 입금 기한이 7일로 안내되는가
5. **[카드 · 간편결제]** 탭 클릭
6. **확인** — 「신용카드 · 계좌이체 · 가상계좌 · 네이버페이」가 표시되는가
7. 이름·연락처를 비운 채 **[주문하기]** 클릭
8. **확인** — "이름과 휴대전화를 입력해 주세요." 문구가 뜨는가
9. **여기서 중단** — 정보를 채우고 주문하지 마세요

### B-5. 5만원 무료배송 확인

1. 장바구니에 「듀잇 레몬민트」 3개 담기 (59,700원)
2. **확인** — 배송비가 "무료"로 바뀌는가

## C. 관리자 화면

### C-1. 주문 관리

1. `orders.html` 열기
2. **확인** — 입금대기 주문이 표시되는가
3. **확인** — 상단에 계좌 설정과 알림 설정이 보이는가
4. **[카톡 안내]** 클릭 → 팝업이 뜨고 문구가 만들어지는가
5. 탭(입금 안내 / 입금 확인 / 발송 안내 / 수령 확인)을 바꿔가며 문구가 달라지는가
6. **[문구 복사]** 클릭 → "복사됨" 표시되는가
7. **[닫기]** 로 팝업 종료
8. **⚠ [입금 확인]·[발송 처리]는 누르지 마세요**

### C-2. 재고 관리

1. `stock.html` 열기
2. **확인** — 상품 11개의 재고가 표시되는가
3. **확인** — 품절 경보가 정확한가
4. **⚠ [일괄 채우기]는 누르지 마세요**

### C-3. 정기구독

1. `subs-admin.html` 열기
2. **확인** — 현황 4칸(입금 대기·구독 중·오늘 발송·월 예상 매출)이 보이는가
3. **확인** — 구독 상품 4종의 금액이 표시되는가
4. **⚠ 금액 [저장]은 누르지 마세요**

### C-4. 마케팅 발송

1. `campaign.html` 열기
2. 채널 「문자」 선택, 상품 하나 체크
3. **[문구 자동 작성]** 클릭
4. **확인** — 상품명·가격이 들어간 문구가 만들어지는가
5. **확인** — 글자수와 「SMS (1건 차감)」이 표시되는가
6. **[대상 명단 내려받기]** 클릭 → CSV가 받아지는가
7. **⚠ [지금 발송]은 절대 누르지 마세요**

### C-5. AI 도구

1. `export-ai.html` 열기 → 로그인 유지 확인
2. 국가에 `United States` 입력, 「바이어 메일」 선택
3. **[문서 생성]** 클릭 (AI 비용 약 50원 발생, 1회만)
4. **확인** — 20~30초 후 영문 메일이 생성되는가
5. `dev.html` 열기
6. **확인** — 모델 목록에 Opus·Sonnet 등이 표시되는가
7. **⚠ [수정안 만들기] 이후 [사이트에 반영]은 누르지 마세요**
